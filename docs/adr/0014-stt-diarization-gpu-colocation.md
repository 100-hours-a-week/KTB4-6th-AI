# ADR-0014: Nemotron과 Qwen을 같은 GPU worker에 배치하고 여러 회의가 공유한다

## Status

Accepted

---

## Context

[ADR-0012](0012-modal-realtime-stt-serving.md)에 따라 음성 모델을 Modal에서 직접 서빙하고, [ADR-0013](0013-nemotron-qwen3-batch-speech-pipeline.md)에 따라 Nemotron이 찾은 화자 구간을 Qwen3-ASR 배치로 전사한다. 이 파이프라인을 구현하려면 두 모델을 같은 GPU worker에 둘지, 모델별 GPU worker로 나눌지 결정해야 한다.

Nemotron은 회의 음성을 계속 받아 화자 상태를 갱신하고, Qwen은 화자 구간이 닫힐 때 해당 음성을 전사한다. 두 모델은 같은 음성을 사용하지만 실행 주기가 다르다. 같은 GPU에 두면 음성과 상태를 한 worker에서 관리하며 처리 여력을 공유할 수 있고, 분리하면 모델별 부하에 맞춰 GPU와 worker 수를 조절할 수 있다.

여러 회의가 worker를 공유할 때는 모델만 공유하고 회의별 화자 캐시·음성 버퍼·열린 구간·전사 작업은 분리해야 한다. 같은 GPU를 사용하더라도 Nemotron과 Qwen의 프로세스와 Python 의존성 환경은 각각 유지할 수 있다.

---

## Decision Drivers

- **발화 구간 종료 후 p95 10초 이내에 결과를 제공해야 한다.** 같은 GPU에서의 모델 간 자원 경합과, 모델을 분리했을 때의 음성 전달·처리 대기 시간을 함께 고려한다.
- **회의별 상태와 음성 전달을 단순하게 관리해야 한다.** 연속 화자 상태, 원본 음성, 닫힌 구간과 전사 결과가 같은 회의에 연결돼야 한다.
- **여러 회의가 GPU 자원을 효율적으로 사용할 수 있어야 한다.** 회의마다 모델을 중복 적재하지 않고, 여러 회의에서 발생한 전사 작업을 배치로 처리한다.
- **회의 수 증가에 맞춰 처리 용량을 늘릴 수 있어야 한다.** 회의를 worker에 배정하고 동일한 구성의 worker를 추가하는 방식으로 확장한다.

---

## Considered Options

### 1. Nemotron과 Qwen을 같은 GPU worker에 배치한다

worker마다 Nemotron과 Qwen을 한 번씩 적재하고 여러 회의가 공유한다. Nemotron이 화자 구간을 닫으면 worker 내부의 원본 음성 버퍼에서 해당 구간을 잘라 ASR 작업을 만든다. Qwen은 여러 회의에서 모인 구간을 배치로 전사하고, 각 결과를 원래 회의와 구간에 돌려준다.

**장점**

- 구간 음성을 다른 GPU worker로 보내는 전송 경로와 모델별 라우팅이 필요 없다.
- 화자 캐시·음성 버퍼·열린 구간·전사 작업을 같은 worker에서 관리할 수 있다.
- 회의마다 모델을 적재하는 대신 여러 회의가 모델을 공유하고, 닫힌 구간을 ASR 배치로 묶을 수 있다.
- 같은 구성의 worker를 추가해 회의를 분산할 수 있다.

**단점**

- 두 모델이 GPU 메모리와 연산 자원을 공유하므로, ASR 요청이 몰리면 화자분리 처리에도 영향을 줄 수 있다.
- 한 모델에만 부하가 늘어도 두 모델이 들어 있는 worker를 함께 증설해야 한다.
- worker 장애나 재배포가 배정된 회의의 화자분리와 전사에 함께 영향을 준다.

### 2. Nemotron과 Qwen을 모델별 GPU worker로 분리한다

Nemotron worker가 회의별 화자 상태와 원본 음성을 유지한다. 구간이 닫히면 PCM과 회의 문맥을 Qwen worker로 전송한다. Qwen worker는 여러 Nemotron worker에서 온 구간을 배치로 처리하고 결과를 반환한다.

**장점**

- 모델별 부하에 맞춰 GPU 기종과 worker 수를 조절할 수 있다.
- 두 모델의 GPU 자원 경합과 worker 장애 영향을 분리할 수 있다.
- 여러 화자분리 worker에서 발생한 요청을 Qwen worker에 모아 배치 처리할 수 있다.

**단점**

- 구간 PCM 전송, Qwen worker 선택, 회의·구간별 응답 연결이 추가된다.
- 화자분리와 전사 worker 집합의 용량·대기열을 따로 관리하고 처리 속도를 맞춰야 한다.
- 한쪽 GPU에 여유가 있어도 다른 쪽의 대기 작업이 그 자원을 바로 사용할 수 없다.

### 같은 GPU 자원에서의 통합·분리 비교

각 구성에 **A10 4대, GPU당 CPU 4개·RAM 16 GiB**를 배정하고, **8개 회의 입력을 각각 5분씩 1배속**으로 처리한다. 입력 일정과 최종 506개 화자 구간·PCM이 같은 조건이다. 통합 구성은 worker당 회의 2개를 맡고, 분리 구성은 실제 구간 PCM을 Modal RPC로 전송한다.

| 구성 | GPU 배분 | 성공 전사 / 전체 구간 | 전사 지연 p95 | 최대 지연 | 10초 초과 성공 전사 |
| --- | --- | ---: | ---: | ---: | ---: |
| 통합 | Nemotron + Qwen worker 4대 | 505 / 506 | **4.44초** | 5.76초 | 0건 |
| 분리 1:3, 참고 실행 | Nemotron 1대 + Qwen 3대 | 503 / 506 | 4.63초 | 15.24초 | 7건 |
| 분리 2:2 | Nemotron 2대 + Qwen 2대 | 505 / 506 | **4.31초** | 6.56초 | 0건 |
| 분리 3:1 | Nemotron 3대 + Qwen 1대 | 505 / 506 | 5.12초 | 7.03초 | 0건 |

지연은 구간 음성 종료 예정 시각부터 공통 CPU 수신기에 결과가 도착하기까지이며, 성공 전사를 기준으로 집계한다. 구간 종료 대기·모델 처리·대기열·worker 간 전달을 포함한다.

가장 빠른 분리 2:2와 통합의 p95 차이는 **0.13초, 약 3%**다. 둘 다 10초 목표를 만족하므로, 이 정도 차이보다 구간 PCM 전송과 회의 상태 관리에 필요한 구성을 줄이는 쪽을 우선한다.

분리 1:3에서는 구간 전달 RPC 4건이 **11.69~12.73초** 걸리고, 뒤의 작업은 전송 시작까지 최대 **9.58초** 기다린다. 같은 시기의 ASR 처리 p95는 2.01초로, 이 구간의 지연은 모델 추론보다 worker 간 전달에서 발생한다. 분리 3:1에서는 Qwen worker 한 대에 작업이 모여 ASR 큐 대기 p95가 통합의 **1.16초→1.64초**로 늘어난다. [통합·분리 비교 보고서](../private/topology-comparison-20261017/report.md) · [성공 전사·단계별 집계](../private/topology-comparison-20261017/diagnostics.json)

### 통합 worker에서의 회의 동시 처리

통합 구성이 여러 회의를 수용하는지도 별도로 확인한다. **A10 한 대·CPU 4개·RAM 16 GiB**에 Nemotron과 한국어 특화 Qwen을 함께 적재하고, 회의별로 5분 PCM을 1배속 전송한 결과다. ASR 배치는 최대 8개 구간으로 구성한다.

| 동시 회의 수 | 정상 완료 | 수신 전사 수 | 구간 종료→수신 p95 | ASR 큐 대기 p95 | ASR 배치 처리 p95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 4개 | 4 / 4 | 196개 | 3.90초 | 0.66초 | 1.80초 |
| 6개 | 6 / 6 | 295개 | 4.20초 | 1.15초 | 1.95초 |
| 8개 | 8 / 8 | 392개 | 4.32초 | 1.24초 | 1.97초 |
| **10개** | **10 / 10** | **492개** | **4.76초** | **1.46초** | **1.96초** |

동시 입력을 4개에서 10개로 늘려도 ASR 배치 처리 p95는 **1.80~1.97초**를 유지한다. 10개 입력의 구간 종료→수신 p95는 **4.76초**이고, GPU 메모리 표본 최대는 **8,746 MiB**다. 회의별 상태를 분리하면서 모델과 배치 실행을 공유하는 구성으로 10개까지 지연 목표를 만족한다. [동시 처리 보고서](../private/modal-stt-capacity-20261024/report.md) · [4·6·8·10개 집계](../private/modal-stt-capacity-20261024/results.json)

## Decision

**Nemotron과 Qwen을 같은 GPU worker에 배치하고, 여러 회의가 모델을 공유하되 회의별 상태는 분리한다.**

같은 GPU 자원에서 모델별 분리가 제공하는 지연 이득은 작고, 통합 구성은 구간 음성의 worker 간 전송과 모델별 라우팅을 없앨 수 있다. 전사 요청을 모델별 worker로 다시 배정하는 대신, 회의를 하나의 worker에 배정하고 그 안에서 화자분리와 전사를 이어 처리한다.

worker 내부의 역할은 다음과 같이 나눈다.

- Nemotron은 회의별 화자 캐시를 유지하며 연속 음성을 처리한다.
- 각 회의는 PCM 버퍼·열린 화자 구간·문맥·전사 순번을 따로 유지한다.
- 닫힌 구간은 공유 ASR 큐에 넣고, Qwen은 여러 회의의 구간을 최대 8개씩 배치 처리한다.
- 배치 결과는 작업에 연결된 회의와 구간으로 반환하고, 회의 종료 시 해당 회의의 상태를 정리한다.
- Nemotron과 Qwen은 같은 GPU를 사용하되 프로세스와 의존성 환경을 분리한다.

초기 worker당 동시 회의 한도는 **10개**로 둔다. 회의 수가 늘면 같은 구성의 worker를 추가하고 새 회의를 배정한다. 모델별 독립 확장보다 회의 단위의 배정과 증설을 기본으로 한다.

---

## Consequences

### Positive

- 연속 화자분리와 구간 전사가 같은 GPU의 처리 여력을 공유한다.
- 회의마다 모델을 중복 적재하지 않고, 여러 회의의 구간을 ASR 배치로 처리할 수 있다.
- 구간 PCM의 worker 간 전송과 모델별 라우팅을 줄인다.
- 회의 상태와 종료 정리를 한 worker에서 관리하고 동일한 구성으로 증설할 수 있다.

### Negative

- ASR 부하가 커지면 같은 GPU의 Nemotron 처리에도 영향을 줄 수 있다.
- 한 모델의 부하만 늘어도 통합 worker를 함께 증설해야 한다.
- worker 장애나 재배포가 배정된 회의들의 화자분리와 전사에 함께 영향을 준다.
- 진행 중인 회의를 다른 worker로 옮기려면 화자 캐시·음성 버퍼·미완료 작업을 함께 옮겨야 한다.

---

## Reconsideration Conditions

- 두 모델의 자원 경합으로 구간 종료→결과 수신 p95가 10초를 반복해서 넘거나 처리 대기열이 지속해서 증가할 때.
- 모델 변경이나 발화량·겹침 증가로 Nemotron과 Qwen에 필요한 GPU 자원·증설 비율이 크게 달라질 때.
- 모델별 배포와 장애 영향을 분리하거나 진행 중인 회의를 worker 간 재배치할 필요가 생길 때.
